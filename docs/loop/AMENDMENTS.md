### AMM-010 单目标连续循环(goal 校验驱动)— ADOPTED(2026-10-01)
- 提案:GOAL-PROMPT v4.0→**v4.1**——驱动模型自"一会话=一轮,合轮等
  点火"改为"**一会话=一个连续循环**:用户点火一次=一个循环,循环内
  由 goal 校验驱动连续轮次迭代,直到**单目标**(goal_queue 清空或推进
  至 BLOCKED-HUMAN,点火时可改指)达成或合法终止方停。三处改订:①
  开篇承重句(一次 Go 轮次→一个连续循环);②步骤 3 尾(删锁等点火→
  合轮 touch 刷新循环锁,下一轮由 goal 校验驱动);③终止铁律换形
  ("轮次终止仅四因①协议走完合轮"→"循环终止仅四因①单目标达成";
  "绝不中途弃轮"语义保全,作用域=轮内)。
- 依据:用户指令(会话 2026-10-01,轮 16):"为什么不能只有一个目标
  我想要的是不断通过 goal 校验的模式 不断循环起来"——两级目标(会话
  目标=一轮/研究目标=队列)被用户判定为反直觉,要单目标+校验循环。
- 语义保全:21 承重句 fragment 全部零改动(不变式测试同 commit 验证
  绿);"禁 cron/定时/心跳监听"原样保留——连续循环活在会话内由 goal
  校验驱动,外部调度器仍禁;空转闸(连续 3 次空审计轮⇒PARKED)原样
  保留=连续循环的防呆(训练在途无活时最多 3 轮空转即停,等下次点火);
  PARKED 墓碑/锁判读证据链/每轮原子提交存档点全部不动——AMM-003 防
  的三事故(挂起停摆/关机全损/双开)由增量落盘+幂等发射+双开防护+
  存档点承担,与连续性正交,防御已到位故可放宽驱动模型。
- AMM-003 条款关系:取代其"每轮=一会话"的粒度约定;"拉式点火+
  禁外部调度"内核保留(点火单位从轮升为循环)。

### AMM-008 社区蒸馏门:问表驱动的定向外部经验获取 — ADOPTED(2026-10-01)
- 提案:蒸馏门(AMM-005)的内环只蒸馏自有经验;补外环——**检索前必填
  问表**(四栏:现状/问题/目标/**检索颗粒度**),按颗粒度对齐纪律去社区
  (论文/官方博客/开源项目/社区讨论)获取有效经验,入账 RSI-HORIZON。
  协议全文=RSI-HORIZON.md「社区蒸馏门协议」区;触发=①例行每 ~10
  产出轮(与 HORIZON 复检同步)②现象驱动:同一 current_variable 连续
  ≥2 轮 NOT-Achieved 无进展,或判读出现需外部先验的分叉③用户点名。
- 依据:用户指令(会话 2026-10-01,轮 9):"我说社区蒸馏门的话,我至少
  要总结现状、问题、目标,然后再去对齐细的颗粒度去社区获取有效的
  经验。"轮 8 的手工检索(8 体系对标)即此门的非机制化预演,本提案
  把它变成带纪律的轮内动作。
- 颗粒度对齐纪律(用户规格的核心):检索词必须落在"别人也遇到过的
  那个问题层级"——太抽象(检索不到)或太项目特定(无人写过)都算
  不对齐,须重写再检;每次 ≥2 独立来源交叉,单源=待验证标记。
- 入账判定四分法沿用 HORIZON:已具备/缺口⇒AMM 候选/条件触发/拒;
  **拒绝也留痕**(防重复检索);采纳仍走 AMENDMENTS,本门不改判据、
  不碰宪法正文(问表=HORIZON 协议区,非 GOAL-PROMPT;轮次性触发
  不进每轮协议,保 prompt 精简)。
- 零定时约束不变:检索只发生在轮内,禁后台监听/cron。

- 提案:驱动模型自"cron/心跳马拉松会话"改为**用户 Go 点火的拉式自包含

  删锁合轮。**禁 cron/launchd/定时任务/心跳监听**,调度工具一律不创建;
  ignite.sh 降级为可选后备(仅用户显式要求时启用),非驱动主路径。

  (拉式换形:轮次可以且应当结束——提交即合轮;但三查/路由/门禁/提交

  "轮内协议完整性"。不变式测试同提交更新(fragment 换形,其余 16 条
  零改动)。
- .loop-lock 语义变更:心跳存活信号 → **轮内互斥锁**(goal_check 轮内
