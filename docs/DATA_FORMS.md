# DATA_FORMS — 数据形态规范（类脑训练的数据-目标匹配）

> 核心原则：**数据形态必须匹配训练目标，而不是匹配架构名。**
> 类脑架构在训练质量上的问题，一半来自"用错形态的数据"——不是数据脏，
> 是数据的结构维度（时标层级、情节顺序、动作耦合）与目标函数的结构不匹配。

## 1. 分线匹配表

| 线 | 训练目标 | 正确数据形态 | 传统 LLM 语料？ | 理由 |
|---|---|---|---|---|
| M1-2B（语言主线） | next-token 因果 LM | 扁平 token 语料 | ✅ 合适 | 目标就是 LM；GWT/睡眠/EWC 是外挂，不改变主目标。勿给语言线造"脑型数据"（cargo-cult） |
| M1-128M | next-token | 扁平 token 语料 | ✅ | 同上 |
| O1-Sound | 逐帧唤醒分类 | 音频帧流（log-mel） | — | 已经是正确形态 |
| **世界模型线（JEPA）** | **隐空间状态预测** | **观测-动作-时间轨迹** | ❌ 不合适 | JEPA 预测隐状态演化，不是 token 接龙；文本喂 JEPA = 目标错配 |
| 类脑模块（持续学习/记忆） | 顺序任务适应、防遗忘 | **情节流**（顺序经历 + 重放） | ⚠️ 形态错误 | shuffle 成 batch 摧毁时序结构；可塑性/睡眠巩固假设的就是顺序经历 |
| 参数化记忆 | K→V 绑定召回 | 键值绑定序列（已有 cross-window recall 探针） | 部分 | 用探针评估，不靠 PPL |

## 2. 情节流格式（episodic stream spec）

类脑模块与世界模型线的统一输入形态。一个"情节" = 一段有起点、有因果、可重放的经历：

```
episode {
  id, time_base               # 时间锚点
  stream: [                   # 多时标层级
    {t, obs[], act[]?, reward?}   # 细粒度步（传感器帧级，对应短 τ）
    {t0, t1, label}               # 事件段（工况/任务级，对应中 τ）
    {meta}                        # 情节级元信息（长 τ / 睡眠巩固单位）
  ]
  actions?: [ ... ]           # 世界模型线必填；纯感知线可空
  reward?: scalar             # 类脑 RL/agentic 线用
}
```

三条纪律：

1. **流式而非语料式**——`(obs, act, t)` 三元组，时间戳是一等公民（不规则采样
   是特性不是缺陷；NASA 电池/DVS 已是此形态）。
2. **多时标层级**——τ 阶梯（10-240ms）对应物理时标：帧→事件→情节。
   文本 token 没有这个维度，这就是音频/传感器天然适配、文本要绕路的原因。
3. **情节性**——"先经历 A、后经历 B、再回忆 A"，不允许均匀混合。
   M2 的 nchain（任务链）与 genreplay（生成式重放）是本格式的已验证实现。

## 4. 反模式清单（禁止）

1. ❌ 把世界模型线跑在文本语料上（目标错配）
2. ❌ 给语言主线造"脑型数据"（cargo-cult；LM 目标就该用 LM 语料）
3. ❌ 用 shuffle 后的 flat batch 评估可塑性/睡眠巩固（摧毁时序）
4. ❌ 用纯 PPL 衡量类脑架构（RESULTS.md 已定：立论在记忆/效率，不在 LM 质量）
5. ❌ 无时间戳的合成序列伪装成"流"（没有真时标，τ 阶梯失去意义）

## 5. 行动顺序

1. 世界模型线：只用 §2 情节流（已写入 AwareLiquid-World/PLAN.md 数据策略）
2. M2 类脑实验：nchain/genreplay 沉淀为 §2 的正式实现 + 文档（本文件落地）
3. M1-2B：语料不动；评估补记忆/时序探针（cross-window recall 已有，扩到 2B 规模）
4. 新增实验必须声明其数据形态（流/情节/语料），不声明的按反模式 5 处理
